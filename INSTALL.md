# Установка агентом

Этот репозиторий — пустой переносимый механизм. В нём не должно быть памяти,
личных данных или путей с машины автора.

## Задача агента

1. Клонируй репозиторий в постоянный каталог пользователя.
2. Спроси, какой движок использовать для фоновой обработки: `haiku`, `luna`
   или `grok`. Не выбирай молча.
   - Если установку ведёт Claude и другой подписки нет, рекомендуй `haiku`.
   - Если установку ведёт Codex и другой подписки нет, рекомендуй `luna`.
   - `grok` предлагай как отдельную подписку, позволяющую не расходовать лимиты
     основного агента.
3. Отдельно спроси о fallback (`haiku`, `luna`, `grok` или без fallback).
4. Проверь наличие `uv` и CLI выбранных движков в `PATH`: `claude` для Haiku,
   `codex` для Luna, `grok` для Grok.
5. Спроси или достоверно определи каталоги проектов. Не сканируй и не выбирай
   весь домашний каталог автоматически.
6. Установи зависимости: `uv sync`.
7. Запусти установщик из корня клона, передав уже подтверждённый выбор:

```bash
uv run python scripts/install.py \
  --caller codex --engine luna --fallback none \
  --root "/путь/к/каталогу-с-проектами" \
  --project "/путь/к/конкретному-проекту"
```

Если `--engine` не передан, установщик сам задаёт оба вопроса интерактивно.
`--caller claude` рекомендует Haiku, `--caller codex` — Luna. Рекомендация не
подменяет выбор пользователя.

Установщик сам делает короткий реальный запрос к каждому выбранному движку.
Если CLI отсутствует, подписка недоступна или вход просрочен, он печатает
`PARTIAL`, объясняет проблему простым языком и даёт действие для исправления.

`--root` и `--project` можно повторять. `--root` разрешает SessionStart
автоматически инициализировать дочерние проекты. `--project` сразу создаёт в
проекте `AGENTS.md`, указатель `CLAUDE.md`, `wiki/`, `daily/` и Codex Stop-hook.

Установщик сам вычисляет абсолютный путь своего клона и записывает его только в
локальные настройки этой машины: `~/.claude/settings.json`,
`auto-init-roots.json`, `engine.json` и `.codex/hooks.json` выбранных проектов.
Повторный запуск безопасен и не дублирует хуки.

Если Claude Code не используется, добавь `--no-claude`. При отказе основного
движка система сообщает ошибку и запускает выбранный fallback. Если оба
недоступны, материал остаётся в очереди для повторной обработки.

Новый провайдер вроде DeepSeek добавляется одним адаптером в
`scripts/model_client.py`; остальная цепочка памяти от конкретного движка не
зависит.

## Проверка после установки

Агент обязан проверить цепочку по порядку и не объявлять общий успех по одному
успешному шагу:

1. Конфигурация читается, выбранные CLI доступны и отвечают.
2. Hook установлен и запускается без ошибки.
3. Тестовый чат в выбранном проекте попадает в `daily/YYYY-MM-DD.md`.
4. Принудительный запуск `compile.py` переносит тестовое знание в `wiki/` и
   обновляет `wiki/index.md`.

Если среда позволяет создавать отдельный чат, агент проводит полный E2E-тест
через него. Если не позволяет, он выполняет доступные локальные проверки, но не
выдаёт их за полный E2E-тест.

Любой невозможный или неуспешный шаг должен быть явно указан в итоговом отчёте:

- что именно не выполнено;
- точная ошибка или ограничение среды;
- что из-за этого остаётся непроверенным или не работает;
- конкретная команда или действие пользователя для исправления;
- какой тест повторить после исправления.

Запрещено молча пропускать проверку, скрывать fallback как успех основного
движка или писать «установка завершена», если хотя бы один обязательный шаг не
прошёл. Допустимые итоги: `OK`, `PARTIAL` с перечисленными ограничениями или
`FAILED` с инструкцией по восстановлению.

## Перед публикацией

Проверь:

```bash
rg -n '/Users/[[:alnum:]_.-]+/|/home/[[:alnum:]_.-]+/' . \
  --glob '!.git/**' --glob '!uv.lock'
uv run python -m unittest discover -s tests -v
```

Первый вызов не должен находить реальные пользовательские пути. Не коммить
`daily/`, `wiki/`, `sources/`, `.cmc/`, `ACCESS.md`, `.cmc-config.json`,
`auto-init-roots.json`, `engine.json`, логи и локальные настройки.
